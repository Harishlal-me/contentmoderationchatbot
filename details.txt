1. PROJECT OVERVIEW
================================================================================

WHAT THE PROJECT DOES:

CyberGuard AI is an intelligent content moderation and interactive learning
system that detects cyberbullying and toxic content in text using advanced
AI models. The system analyzes user input, classifies severity levels, 
suggests safer alternatives, and provides interactive learning modules through
quizzes and assessments.

The platform combines a BERT-based deep learning classifier with LLM-powered
conversational capabilities to create a comprehensive tool for identifying
harmful content while educating users about cybersecurity and digital safety.


REAL-WORLD PROBLEM IT SOLVES:

* Cyberbullying Detection: Automatically identifies toxic, abusive, and 
  harassing content across digital platforms.

* Social Media Safety: Protects communities by flagging potentially harmful
  messages before they reach other users.

* Educational Need: Provides interactive training to help users understand
  what constitutes cyberbullying and how to respond safely.

* Content Moderation at Scale: Reduces manual moderation load by 
  automatically analyzing large volumes of user-generated content.

* Responsible AI: Demonstrates prompt engineering techniques to guide AI
  systems away from generating harmful content.

4. SYSTEM WORKFLOW
================================================================================

STEP 1: USER INPUT RECEPTION
- User submits text through web interface or chat input field
- Input can be a simple message, analysis request, or query
- Request is received by FastAPI backend at /api/chat endpoint
- Conversation history is maintained for context

STEP 2: INTENT DETECTION
- ChatController analyzes the user input text
- Checks for analysis triggers: "analyze", "classify", "detect", "moderate"
- Checks for explanation prefixes: "what is", "explain", "how does"
- If text starts with explanation prefix → Chat Mode
- If text contains analysis trigger → Analysis Mode
- Default: Chat Mode for general conversation

STEP 3: CHAT MODE (General Conversation)
- Input is sent to LLMHandler for response generation
- Ollama processes request using prompt templates
- Graceful fallback responses if Ollama is offline
- Context-aware responses based on system prompts

STEP 4: ANALYSIS MODE (Cyberbullying Detection)
- Input is forwarded to BertInferenceModule
- BERT classifier analyzes the text
- Output: Label (CYBERBULLYING/SAFE) + Confidence Score
- JSON response includes:
  * Original text
  * Classification label
  * Confidence percentage
  * Threat boolean flag

STEP 5: ENRICHMENT & EXPLANATION
- If cyberbullying detected, LLM generates:
  * Detailed explanation of why it's flagged
  * Severity classification (Low/Medium/High)
  * Safer alternative wording
  * Educational context about the harm

STEP 6: RESPONSE STREAMING
- FastAPI streams response to frontend in chunks
- BERT analysis sent first as JSON separator
- LLM-generated text streamed progressively
- Frontend receives streaming updates in real-time

STEP 7: MODE SWITCHING
- Quiz Mode: User requests quiz → QUIZ_PROMPT activated
- Assessment Mode: User requests assessment → ASSESSMENT_PROMPT activated
- Switch triggers automatic mode change in LLM system prompt
- Mode-specific response generation for each context

6. QUIZ MODULE DESCRIPTION
================================================================================

PURPOSE:
The Quiz Module provides interactive, gamified learning to help users
develop cyberbullying detection skills through continuous practice.

HOW QUIZ WORKS:
1. User requests a quiz with optional difficulty specification
2. Chat controller activates QUIZ_PROMPT mode
3. LLM generates contextual cyberbullying scenario questions
4. Questions are presented one at a time
5. User provides answers through chat interface
6. System validates responses and provides immediate feedback
7. Score is calculated based on correct answers
8. Quiz continues until completion or user exit

MCQ FORMAT:
- Multiple Choice Questions with 4 options (A, B, C, D)
- Each question presents a realistic cyberbullying scenario
- Scenarios include:
  * Group chat harassment
  * Targeted insults
  * Social exclusion
  * Exclusionary language
  * Context-dependent harmful text
  * Edge cases with ambiguous intent

ANSWER VALIDATION:
- Exact match checking against generated correct answer
- Partial credit for partially correct responses
- Explanation provided for why answer is correct/incorrect
- Educational feedback helps users understand the concepts
- No penalty for wrong answers except missing score points

SCORE CALCULATION:
- Total Questions: 5 per quiz session
- Points Per Question: 1 point for correct answer
- Calculation: (Correct Answers / Total Questions) × 100 = Percentage
- Final Score Display: "Score: 4/5 (80%)"
- Performance Rating:
  * 90-100%: Expert Level
  * 70-89%: Proficient
  * 50-69%: Basic Understanding
  * Below 50%: Needs Practice


7. ASSESSMENT MODULE DESCRIPTION
================================================================================

PURPOSE:
The Assessment Module provides comprehensive, paragraph-based evaluation
exercises to assess and train users on identifying cyberbullying in
complex, realistic contexts.

EVALUATION APPROACH:
1. Multi-paragraph scenarios are presented to users
2. Context is provided before the harmful content
3. Users are asked targeted questions about the content
4. Assessment focuses on critical thinking and context awareness
5. Responses are evaluated for comprehension and safety awareness

MCQ FROM CONTEXT:
- Questions generated directly from paragraph scenarios
- Multiple choice format with 4-5 options per question
- Questions test:
  * Ability to identify subtle cyberbullying
  * Understanding of context and intent
  * Recognition of harm patterns
  * Knowledge of severity levels
  * Application of moderation policies

LEARNING-FOCUSED EVALUATION:
- Emphasis on understanding over rote memorization
- Constructive feedback explaining incorrect answers
- Examples provided to illustrate concepts
- Links between theory and real-world scenarios
- Progressive difficulty increase through modules

ASSESSMENT SESSION FLOW:
1. Welcome message explaining assessment format
2. Scenario introduction: "Read this paragraph carefully..."
3. Paragraph text provided (3-5 sentences)
4. Question posed: "What type of cyberbullying is this?"
5. User selects multiple choice answer
6. Feedback provided immediately
7. Next scenario presented or summary given


8. CHALLENGES FACED
================================================================================

CHALLENGE 1: MODEL REFUSING HARMFUL CONTENT
────────────────────────────────────────────
Issue: LLM models frequently refused to analyze or discuss harmful content,
even in educational context. Examples:
- Ollama LLaMA refusing to explain why messages were harmful
- Generic "This content is inappropriate, I can't discuss" responses
- Inability to generate safer alternatives without detailed prompts
- Loss of educational value due to excessive content filtering

Impact: System could detect harmful content but couldn't provide learning
value through explanations and education.

CHALLENGE 2: EXPLANATION AND REWRITE PROMPT ENGINEERING
─────────────────────────────────────────────────────────
Issue: Initial attempts to generate explanations produced:
- Vague, non-specific responses
- Generic explanations lacking educational content
- Rewrites that didn't preserve original intent
- Overly lengthy explanations reducing user engagement

Solution Attempt: Created explicit prompt templates with:
- Specific output structure requirements
- Format specifications (JSON, structured text)
- Clear examples of desired output quality
- Tone and style directives

CHALLENGE 3: UI/UX IMPROVEMENTS
─────────────────────────────────
Issue: Initial web interface had usability problems:
- Chat messages displayed as raw JSON with BERT data
- No clear visual distinction between analysis and chat modes
- Difficult to read streaming responses
- Poor responsiveness on different screen sizes
- No visual feedback for loading states

Solution: 
- Developed React + Tailwind CSS modern interface
- Separated BERT diagnostic data from user-visible output
- Added visual indicators for different response types
- Implemented smooth animations and loading indicators
- Streamlit alternative UI for quick iteration

CHALLENGE 4: INTENT DETECTION ACCURACY
────────────────────────────────────────
Issue: System struggled to distinguish between:
- "What is cyberbullying?" (knowledge question, Chat Mode)
- "Analyze: Is this cyberbullying?" (analysis request, Analysis Mode)
- Ambiguous inputs that could be either mode

False Positives: Explanation questions triggered analysis mode
False Negatives: Some analysis requests treated as chat queries

Solution: Multi-rule detection system created:
- Explicit analysis trigger keywords list (50+ terms)
- Explanation prefix detection (what is, explain, how does, etc.)
- Rule priority: Explanation prefixes override analysis triggers
- Contextual analysis based on sentence structure
- Accurate mode classification achieved > 95% accuracy

CHALLENGE 5: RESPONSE STREAMING ARCHITECTURE
──────────────────────────────────────────────
Issue: Initial single response approach was inefficient:
- Users waited for full LLM generation before seeing anything
- No indication that processing was happening
- Poor perceived performance on slower hardware
- Difficult to display BERT and LLM data together

Solution: Implemented streaming architecture:
- FastAPI StreamingResponse for progressive output
- BERT analysis sent first as JSON delimiter
- LLM-generated text follows for progressive display
- Frontend parses streaming data structure
- Improved perceived performance significantly

SOLUTION 1: MASTER PROMPT DESIGN WITH MODE-SPECIFIC TEMPLATES
──────────────────────────────────────────────────────────────
Implementation:

Key Features:
- Prompts explicitly instruct the model to analyze and explain
- Permission frameworks: "You are a content analyst, you should analyze..."
- Structured output specifications in prompts
- Example-driven guidance for response format
- Temperature guidance for consistency vs creativity

Technique Used - Prompt Engineering:
- Forward-compatible instruction design
- Constraint relaxation: Moving restrictions to earlier in pipeline
- Context-based permission frameworks
- Explicit role definitions for different modes

Example Master Prompt Structure:
"You are CyberGuard AI, a content moderation expert. Your role is to:
1. Analyze text for potential harm
2. Explain your reasoning clearly
3. Provide educational context
4. Suggest safer alternatives

When analyzing, follow this structure:
- Identify specific problem language
- Explain why it's harmful
- Rate severity (Low/Medium/High)
- Provide a safer version"


SOLUTION 2: INTELLIGENT MODE SWITCHING LOGIC
──────────────────────────────────────────────
Implementation: Dual-Filter Detection System

Filter 1: Explanation Prefix Check
- Checks if input starts with: "what is", "explain", "how does", etc.
- If true → Force Chat Mode (knowledge seeking)
- Bypasses all other analysis checks

Filter 2: Analysis Trigger Keyword Detection
- 50+ analysis trigger keywords: "analyze", "classify", "detect", "flag"
- Context-aware matching with word boundaries
- Multiple passes to avoid false positives

Mode Decision Logic:
```
if starts_with_explanation_prefix:
    mode = CHAT_MODE  // Explanation questions stay in chat
else if contains_analysis_trigger:
    mode = ANALYSIS_MODE  // User wants analysis
else:
    mode = CHAT_MODE  // Default to chat
```

Result:
- Chat vs Analysis Mode accuracy: >95%
- Reduces false analysis triggers from 40% to <5%
- Improves user experience through appropriate responses
- Enables seamless mode switching based on intent


SOLUTION 3: STRUCTURED OUTPUT FORMATTING
──────────────────────────────────────────
Implementation: JSON-to-Structured-Text Pipeline

For BERT Analysis Output:
```
{
  "text": "[original text]",
  "label": "CYBERBULLYING" | "SAFE",
  "confidence": [0.0-1.0],
  "is_threat": true | false,
  "severity": "Low" | "Medium" | "High"
}
```

For LLM Explanation Output:
Structure enforced in prompt:
- Sentence 1: "[quoted text]"
- Classification: [label]
- Severity: [level]
- Explanation: [educational explanation]
- Safer Alternative: [rewritten text]
- Impact: [harm analysis]

Streaming Output Format:
```
[BERT_JSON]\n|||\n[LLM_STREAMED_TEXT]
```

Frontend Parser:
1. Receives streaming chunks
2. Splits on |||  separator
3. Parses first section as JSON (hidden diagnostic data)
4. Parses second section as user-visible text
5. Progressively displays LLM text as it arrives

Benefits:
- Clean separation of diagnostic and user-facing data
- Structured data for programmatic access
- Human-readable format for end users
- Extensible format for future enhancements


SOLUTION 4: MULTI-TIER FALLBACK SYSTEM
────────────────────────────────────────
Implementation: Smart Fallback Responses

Tier 1 - Primary: Ollama LLM Server
- Fast local inference
- Complete feature support
- Real-time response generation

Tier 2 - Fallback: Context-Aware Hardcoded Responses
- Detects greeting keywords
- Identifies quiz requests
- Detects assessment mode
- Returns appropriate static responses
- Better than generic "server offline" error

Tier 3 - Last Resort: Generic Error Response
- Apologizes for unavailability
- Suggests refreshing or returning later
- Professional error handling

Example Fallback Logic:
```
if is_greeting(user_input):
    return greeting_with_feature_intro()
elif is_quiz_request(user_input):
    return quiz_introduction()
elif is_assessment_request(user_input):
    return assessment_introduction()
else:
    return generic_unavailable_message()
```

Benefit: Maintains usability even with LLM server offline


SOLUTION 5: BERT CLASSIFIER INTEGRATION
─────────────────────────────────────────
Implementation: Production-Grade Wrapper Module

BertInferenceModule:
- Abstracts PyTorch model inference
- Handles tokenization automatically
- Returns structured predictions
- Includes error handling and fallbacks
- Integrates with prediction pipeline

Model Specifications:
- Architecture: BERT-base-uncased
- Max Tokens: 128
- Output: Binary classification (CYBERBULLYING/SAFE)
- Confidence: Probability scores (0.0-1.0)

Pipeline Integration:
1. User input → ChatController
2. Analysis mode detected
3. Text sent to BertInferenceModule
4. Tokenized and padded to 128 tokens
5. GPU/CPU inference executed
6. Prediction returned with confidence
7. Confidence > 0.5 = CYBERBULLYING classification
8. Result sent to LLM for explanation
